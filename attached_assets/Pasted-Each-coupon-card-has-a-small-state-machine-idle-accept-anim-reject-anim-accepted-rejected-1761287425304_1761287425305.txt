Each coupon card has a small state machine: idle → (accept_anim / reject_anim) → accepted / rejected. After an accept/reject animation completes the card shows a Cancel button that returns the card to idle. A bottom fixed action area appears depending on the global set of card states: If any card is rejected → show a bottom fixed Message box + Reject (All) button (Reject button triggers confirmation). If all cards are accepted → show a bottom fixed Accept Trade + Message box. These bars update live when individual cards change state. 2) States (per coupon) idle — default. Visible: Accept and Reject buttons. accept_anim — playing accept animation. During this, disable Accept/Reject taps on that card. accepted — final accepted state. Visible: Cancel button (on the card). reject_anim — playing reject animation. During this, disable Accept/Reject taps on that card. rejected — final rejected state. Visible: Cancel button (on the card). 3) Allowed transitions and triggers idle —[tap Accept]→ accept_anim idle —[tap Reject]→ reject_anim accept_anim —[animation end]→ accepted reject_anim —[animation end]→ rejected accepted —[tap Cancel]→ idle rejected —[tap Cancel]→ idle Notes: While in accept_anim or reject_anim, the card ignores additional Accept/Reject taps (but Cancel should not be visible until animation finishes). Tapping Cancel always immediately restores idle state (no additional animation required unless you want a short reverse animation). 4) Card UI rules idle: show Accept (primary) and Reject (destructive) buttons. accept_anim: optionally show micro-feedback (spinner, shrinking accept button, confetti animation). The Accept/Reject controls are visually disabled. accepted: show a clear Cancel button that reverts the card to idle. Optionally show a persistent accepted badge/icon. reject_anim: show a micro-feedback animation (e.g., slide-out, red pulse). Controls disabled until animation end. rejected: show a clear Cancel button and a small "rejected" visual state (muted card, icon). 5) Bottom-fixed area rules (global derived UI) Let N be total cards and counts be: acceptedCount = number of cards with status accepted rejectedCount = number of cards with status rejected Rules: If rejectedCount > 0: Show bottom-fixed pane containing: Message input area (optional / editable) Reject (All) button (destructive) When bottom Reject is tapped → show confirmation dialog: Title: "Confirm rejection" Content: "Are you sure you want to reject X coupon(s)? This cannot be undone." Buttons: Confirm Reject (finalizes) and Cancel (dismiss) Confirm Reject executes the final rejection action (e.g., send to backend) for those rejected cards. Else if acceptedCount === N: Show bottom-fixed pane containing: Message input area (optional / editable) Accept Trade button (primary) Tapping Accept Trade triggers final acceptance action for all accepted cards (optionally with confirmation). Else: Hide bottom-fixed pane completely. Edge behavior: If a card moves from rejected → idle via Cancel and that was the last rejected card, hide the bottom Reject pane immediately.
