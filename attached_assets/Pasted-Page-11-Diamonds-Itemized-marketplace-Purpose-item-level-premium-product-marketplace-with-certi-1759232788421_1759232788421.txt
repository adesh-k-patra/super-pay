Page 11 — Diamonds (Itemized marketplace)
Purpose: item-level premium product marketplace with certification & inspection.
Catalog listing
* Card per diamond: thumbnail, price, Carat/Cut/Clarity/Color, vendor, certification summary, buyback estimate
Item detail
* High-res images + 360° viewer
* Certificate PDF (GIA/IGI) link
* Detailed specs table (carat, cut, clarity, color, dimensions)
* Vendor profile, return policy, escrow/inspection options
* Optional authenticated inspection: pro-inspector visits or sample check (delayed)
Buy flow
* Escrow required for high-value purchases; inspector verification window (e.g., 48–72 hrs)
* On acceptance or inspection success → funds released to vendor
* Option: Buy with Buyback (if vendor offers buyback guarantee)
Backend
* /api/diamonds/catalog (GET)
* escrow + inspection orchestration /api/escrow/diamond
* certificate verification service
Acceptance criteria
* Certificates downloadable; escrow prevents fund release until verification or acceptance.

Page 13 — AI-Invest (Prominent, model-driven)
Purpose: recommend portfolio mixes; optionally auto-execute and manage.
Top UI
* Simple wizard: Amount now + Monthly contribution + Risk level + Duration + Restrictions
* Preview: recommended allocation donut + top instrument list with vendor tags
* Projected returns (Low / Expected / High) + volatility estimate + estimated fees/taxes
* Explainability: one-line reason per allocation + model metadata (model id/version + last data refresh)
Actions
* Customize → edit allocations by asset class & by-instrument
* Run Simulation → backtest summary (3/5/10 yr)
* Save Plan → store & schedule
* Apply (Auto-Invest) → generate multi-order preview & require explicit consent (mandate for auto SIP or auto-rebalance)
Auto-execution permission
* Show multi-order summary, vendor routing policy, expected execution schedule, total debit, rebalancing frequency
* Require e-mandate / signed consent for recurring flows
* Buttons: Confirm & Authorize (triggers signing) / Cancel
Backend
* /api/ai/plan/create (POST) with model metadata
* backtest engine /api/ai/backtest
* scheduling engine /api/ai/scheduler (fires orders as per plan)
* explainability logs stored for compliance
Acceptance criteria
* Each plan stores model_id & backtest parameters; multi-order preview identical to execution orders.
