Users see wrong behavior when navigating around the app: Tabs on many pages are stored in local component state. When a user navigates away and comes back (or shares a link / reloads), the selected tab is lost. Back button sometimes goes to an unexpected page (doesn't return to the correct section, or returns to a list instead of the previously-opened tab/section). Modal/detail pages opened from a section do not restore the original UI state when hitting back. Some places use window.history or manual DOM navigation instead of react-router primitives. Goal: Make navigation deterministic, bookmarkable, and correct for browser back/forward across the whole app. Follow React Router v6+ best practices and TypeScript. Provide a robust migration, tests, and checklist for PR. High-level strategy (must follow) Canonicalize routing — use react-router routes (or your routing lib) for every screen/section/state that should be linkable/history-aware. Prefer path segments for primary sections and query params for ephemeral switches. Example: /projects/:id/overview, /projects/:id/activity (preferred for SEO & clarity) or /projects/:id?tab=overview (valid for UI-only tab state). Replace local tab state with URL-driven state using either: nested routes (recommended), or useSearchParams() (query param approach). Modal/detail pattern — push the modal route onto history (so Back closes it) and use location.state.backgroundLocation (React Router pattern) to render modal over list while still having a proper URL. Consistent navigation API — use Link, NavLink, and useNavigate() only. Avoid direct window.location or manual history.pushState. Back button behavior — ensure all navigations that should create a history entry use navigate(path) (push) and that navigations that should replace do navigate(path, { replace: true }). Audit & automated checks — find all useState usages tied to "tab" / "activeTab" / "selectedIndex" and refactor. Add lint rules or code comments to prevent reintroducing local-only tab state.
